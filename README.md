# Кабинет здоровья доктора Горшечникова

Одностраничный сайт кабинета здоровья (Салават, ул. Юлаева, 29а, Дом Быта, 3 этаж).

Статический сайт без сборки: `index.html`, `assets/css/style.css`, `assets/js/main.js`, изображения в `assets/img/`.

## Локальный запуск
```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

## Деплой на Vercel
Импортировать репозиторий в Vercel → Framework Preset: **Other**, Build Command пустая, Output Directory — корень (`.`).

## Что стоит подтвердить у клиники
- Акция «Консультация и процедура — бесплатно» (для новых пациентов) — по просьбе клиента.
- Форма записи открывает WhatsApp на номер +7 993 044-06-19 — проверить, что на номере есть WhatsApp.
- Часы работы на сайте не указаны.
- Фото команды пока старые — заменить, когда будут в хорошем качестве.

## SEO
Основной адрес — `https://www.drgorshechnikov.ru` (с www; адрес без www перенаправляется на него настройками домена в Vercel — не добавлять обратный редирект в `vercel.json`, будет петля). Домен прописан в: `index.html` (canonical, og:url, og:image, twitter:image, JSON-LD), `robots.txt`, `sitemap.xml`.
- При правке контента обновить `<lastmod>` в `sitemap.xml`.
- Описания процедур для окна «Подробнее» лежат в HTML карточек (`.dir-card__info`), а не в JS — так их видят поисковики.
- Вопросы FAQ продублированы в JSON-LD (`FAQPage`) — при изменении вопросов править оба места.
- Аватары в первом экране — миниатюры `assets/img/*-thumb.webp` (96×96).

## Дизайн и откат
Тема «белый + индиго» (как в Instagram клиники) лежит в `assets/css/theme-indigo.css` и подключается после `style.css`.
- Вернуть прежние цвета (золото/тёмно-синий): удалить строку с `theme-indigo.css` в `index.html`.
- Вернуть сайт целиком к прежней версии: ветка `backup-gold-navy` на GitHub (или Instant Rollback в Vercel).
Логотип GA: `assets/logo-ga.svg`, фавикон: `assets/favicon.svg`.

## Онлайн-курсы и личный кабинет
Раздел `/kursy/` (каталог, курс, плеер), `/kabinet/` (мои курсы, заказы, профиль) и `/admin/` (курсы, уроки, заказы).

**Где что работает**
- **Вход** — Neon Auth. Браузер ходит на свой домен `/neon-auth/*`, функция `api/neon-auth.js` пересылает запрос
  в Neon Auth (cookie сессии first-party — работает в Safari). Для API сайта берётся короткий JWT (`/neon-auth/token`),
  сервер проверяет его по `/.well-known/jwks.json` (issuer/audience = origin Neon Auth) — `api/_lib/auth.js`.
- **Данные** — Neon Postgres, схема `db/schema.sql`. Функции `api/rpc.js` (каталог, заказы, прогресс, админка)
  и `api/courses.js` (видео). Регион функций — `fra1`, рядом с базой.
- **Видео** — приватный бакет Cloudflare R2. Ссылка на просмотр живёт 10 минут и выдаётся только после проверки
  покупки и единственного устройства; загрузка из админки — подписанный PUT прямо в R2 (до 5 ГБ).
  Прежний файл урока при замене **не удаляется** (ответ `previous_path`).
- **Админ** — email из `ADMIN_EMAIL` и только после подтверждения email кодом (кнопка на странице `/admin/`).
- **Оплата** — вручную: клиент оформляет заказ, админ нажимает «Оплата получена». Повтор ничего не дублирует.
  «Закрыть доступ» останавливает просмотр на всех устройствах.

**Настройки (Vercel → Environment Variables):** `DATABASE_URL`, `NEON_AUTH_BASE_URL` (добавляет Neon),
`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `ADMIN_EMAIL`.
В Neon Auth → Domains должны быть `https://www.drgorshechnikov.ru` и `https://drgorshechnikov.ru`.
В R2 CORS — эти же адреса, методы GET, HEAD, PUT.

**Схема базы** применяется `POST /api/setup` с заголовком `x-setup-token`, только если задана переменная
`SETUP_TOKEN` (32+ символа). Без неё эндпоинт отвечает 404. После применения переменную удалить.

**Проверки:** `pnpm test` — тесты на настоящем Postgres в памяти (PGlite) и с локальными ключами JWT.

Папка `supabase/` — прежний вариант на Supabase (до переезда на Neon), сайт его больше не использует.
